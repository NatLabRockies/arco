Arco API UX Ladder Implementation Notes

Running Decisions

  • Created the GitButler virtual branch api-ux-ladder for this work. The repository is in GitButler workspace mode, so I used the GitButler CLI rather than manually editing GitButler metadata.
  • Treating docs/api-ux-ladder-plan.md as the implementation source of truth, but implementing it as vertical slices. The full plan is intentionally broad; attempting every ladder rung at once would create a high-risk cross-cutting change.
  • First implementation slice: tighten the Python API contract around the documented beginner surface. This means adding explicit axes=... support for parameters/variable arrays and adding result accessor aliases such as result.value(...). This slice is small enough to test directly and establishes the strict primary-subject/keyword-configuration shape from the plan.

Open Notes

  • Labeled array diagnostic hardening: replaced production unreachable! assertions in Python model-edit alignment paths with typed ArrayTypeError returns. The previous branch was logically guarded by an axes attribute check, but user-facing Python paths should fail with ladder diagnostics rather than panic if a malformed labeled object violates that implicit invariant.
  • Xpress availability tests: replaced broad Exception handling with SolverNotAvailableError so the optional-license test path exercises the same typed solver diagnostic contract exposed to users.
  • Warm-start diagnostic wording: removed "yet" from the runtime primal_start rejection messages so the user-facing error describes the current solve-path contract without promising future support. The behavior remains unchanged: empty hints are accepted and non-empty hints raise SolverInvalidSettingError.
  • Core-concepts warm-start wording: updated the explanation docs to describe the current typed solve-setting contract instead of saying warm starts are a planned unsupported feature. Empty starts remain no-ops, while non-empty primal_start inputs fail with a typed solver-setting error.
  • Debug-shell expert API alignment: the CLI IPython bootstrap was still emitting positional raw set_objective(...) calls and referenced raw name setters that were not public Python methods. I made the generated script use keyword-only expert calls and added keyword-only set_variable_name(index=..., name=...) and set_constraint_name(index=..., name=...) as explicit expert APIs, preserving inspectable names for CSC-backed debug shells without making raw IDs part of the beginner path.
  • Decision made for the first Python API slice: remove legacy positional axis forms for the APIs touched by this change. arco.param now uses axes=..., and Model.add_variables now uses keyword-only axes=.... This follows the plan's pre-1.0 compatibility policy and avoids carrying two beginner-facing shapes.
  • Tradeoff: this intentionally breaks existing Python examples/tests that still use positional axes. I updated the focused tests touched for this slice and migrated public docs/examples that exercised this surface so the docs gate proves the beginner path.
  • Follow-up from validation: just docs-test initially failed on stale positional add_variables(...) snippets in docs/how-to/inspect-model.md and docs/how-to/numpy-integration.md. I updated those to axes=(...) rather than retaining compatibility shims, consistent with the plan's pre-1.0 policy.
  • Scope decision: this slice implements the first stable public API contract from the ladder, not the full architecture migration. The plan remains the guide for later work on solver backend ownership, block composition, CLI/KDL alignment, and memory-oriented internals.
  • Diagnostics cleanup: changed the empty-axis error from index_sets must be non-empty to axes must be non-empty so the binding reports the public API term.
  • Example smoke testing found that the ReEDS benchmark's nodal balance combined arrays indexed by directed aliases from and to. Arco correctly rejected subtracting those aliases because they are distinct axes. I did not add a new relabeling primitive in this slice; instead, the example now builds the balance constraints explicitly per region/hour/year using public indexing and reductions. That keeps the alias semantics strict and avoids adding an unplanned API.
  • Second implementation slice: converted the plan's solver-contributor path into docs/how-to/add-solver-backend.md. The guide is grounded in the current ModelViewBackend, ModelViewSolveResult, SolverConfig, and SolverCapabilityModel contracts. It deliberately keeps solver contributors out of Python, KDL, block internals, and primitive model storage unless a shared contract has to change.
  • Third implementation slice: exposed memory-facing sparse array counts on VariableArray. shape and dense_count show the dense indexed domain, while active_count shows how many variables were actually created after applying active=. This makes the sparse/large-model rung more explicit without changing internal storage.
  • Fourth implementation slice: migrated ordinary docs and contract examples from solution.get_value(...), solution.get_dual(...), and solution.get_primal(index=variable) to the ladder-facing solution.value(...) and solution.dual(...) accessors. I left get_primal(index=0) in block extraction examples because those extract hooks currently receive only result/data, not the variable object; changing that would be a separate block API design change.
  • Added docs/migration/api-ux-ladder.md and a migration index to document intentional pre-1.0 old-to-new mappings for param, add_variables, VariableArray sparse counts, and solution accessors. This follows the plan's rule to break unclear APIs before 1.0 while still giving current users a direct migration path.
  • Updated docs/explanation/architecture.md to use the same ownership diagram and architecture rules as the API ladder plan. This keeps the target ownership model visible in the main documentation rather than only in the planning document.
  • KDL parity check found a real beginner-rung gap: scalar control declarations validated and instantiated, but scalar identifiers such as x were not resolved during algebra compilation. I fixed the linear and nonlinear expression resolvers to treat a bare identifier as a variable only when a zero-index variable family exists and the exact scalar instance was instantiated. This keeps unresolved identifiers strict while making the one-screen KDL quickstart runnable.
  • README quickstart now shows the same scalar model in Python and KDL. The larger data-backed/indexed KDL profile remains in tutorials and how-to material, which better matches the ladder progression.
  • Fifth implementation slice: implemented inferred KDL scenarios for the beginner rung. When an entrypoint has no explicit scenario and exactly one model, semantic validation and compilation synthesize a scenario with the model name, no data bindings, no reports, and use pointing at that model. Files with multiple models still require an explicit scenario. This keeps data-backed and multi-model workflows explicit while allowing the first one-screen KDL model to omit scenario boilerplate.
  • Documentation follow-up for inferred scenarios: updated the README KDL language section, the formal Arco spec scenario section, and the missing-scenario diagnostic help so users see the new rule outside the implementation.
  • Block tutorial cleanup: replaced the remaining raw get_primal(index=0) extraction examples with result.value(...) by using the existing block ctx object to carry public variable handles from build to extract. This avoids introducing a new block API while keeping the composition tutorial aligned with the result-accessor ladder.
  • Block adapter fix: the documented ctx pattern exposed that composed solves passed a dict context while typed block adapters expected an object with an inputs attribute. I updated the adapters to accept either an attribute-style context or the existing dict context, preserving the current composed solver path and making public handle extraction work.
  • Architecture boundary hardening: expanded the Python/Rust boundary test so arco-python is explicitly limited to the shared runtime facade and block composition crates among Arco workspace dependencies. This records the ownership rule from the plan in executable tests rather than only documentation.
  • Added a scalar ladder contract test that exercises the first rung as a user-facing workflow: named scalar variables, a named constraint, a named objective, solve, objective value, and result.value(...). This gives the API ladder a direct regression test instead of relying only on docs examples.
  • Added an indexed ladder contract test for IndexSet, param(values, *, axes=..., name=...), variable arrays, reductions, batch constraints, solve, and array-valued result.value(...). The first run exposed that add_constraints(..., name=...) named the model rows but did not preserve names on the returned ConstraintArray handles. I fixed the handle metadata so public handles and inspected model names agree.
  • Added a KDL indexed ladder contract test beside the scalar KDL quickstart tests. The KDL path uses CSV-backed set/parameter declarations, an indexed control, an indexed constraint, an objective reduction, inspect --json structure checks, and a compact solve objective check. Current compact solve counts report KDL templates for this path, so the test verifies instance expansion via inspect metadata instead of pretending the compact summary reports lowered row/column counts.
  • Added a debug/operations ladder contract test for result.value(...), result.slack(...), and result.dual(...) on ordinary scalar handles. This confirms the preferred result accessors are not just aliases in the stub; they are usable in a solved model.
  • Changed CLI run summary counts to report lowered variable and constraint instances instead of KDL declaration templates. This is a breaking pre-1.0 JSON behavior change, but it better matches the memory-first API contract because arco run --compact now exposes the actual row/column count handed to the solver. The indexed KDL contract test was updated to expect two lowered variables and two lowered constraints; the tuple-domain tracer test now expects its actual lowered 4-column, 9-row model size.
  • Removed arco-cli's direct arco-kdl dependency by adding ArcoOps::format_kdl_text to the runtime facade. The CLI formatter now uses the same facade dependency as the rest of the CLI surface. I intentionally made the facade return a string formatting error rather than exporting the parser's concrete KdlError type through arco-ops; formatting only needs a human-facing message today, and keeping the parser error type private preserves the architecture boundary.
  • Added a data-backed model failure contract for a CSV missing the cost column required by a KDL param. One important boundary surfaced while writing it: kdl check and inspect validate/inspect semantic structure, but they do not materialize all parameter values today. The missing-column diagnostic is therefore covered on arco run --compact, where compilation and solve preparation load the data needed by the objective.
  • Added an explicit arco kdl check --materialize-data mode. The default check remains structural and cheap for editor workflows, while the opt-in mode compiles far enough to load CSV-backed parameter values and report data-contract failures without invoking a solver. This closes the missing-column gap for pre-solve validation without making every editor check pay full lowering/materialization cost.
  • Added a solver-contributor contract test in arco-solver for the neutral ModelViewBackendRegistry. The test verifies that shared SolverConfig is passed through unchanged and that a backend returns primal/dual/row vectors aligned to ModelView variable and constraint counts. This turns part of the "add a solver backend" guide into an executable contract.
  • Added stable Python exception codes on Arco exception classes plus an arco.error_code(exc) helper. This gives Python callers a machine-readable diagnostic category without parsing human messages. The first contract covers a parameter shape mismatch as arco::array::shape_mismatch; broader cross-surface equivalence still needs a shared diagnostic registry.
  • Strengthened the memory-first API contract by asserting pre-solve coefficient counts in the indexed ladder test and documenting snapshot.metadata.coefficients in the inspect guide. This makes "how many coefficients will the solver see?" part of the tested beginner-to-indexed workflow, not just an internal snapshot field.
  • Added a first stage-diagnostic primitive for composed Python block solves: result.blocks.statuses() returns a block-name to solver-status map. This keeps block execution inspectable without introducing persisted workflow reports or KDL workflow syntax yet.
  • Added a solver-backend ownership boundary test. Concrete backend crates (arco-highs, arco-scip, arco-xpress, and arco-ipopt) must depend only on the primitive model and solver contracts among Arco crates; they must not depend on Python, CLI, KDL, blocks, validation, or the runtime facade. This turns the solver-contributor architecture rule into a regression test.
  • Added pre-solve expanded KDL inspect counts: meta.counts.variable_instances and meta.counts.constraint_instances. The existing variable and constraint counts remain declaration counts, while the new fields expose the semantic instance totals users need for memory planning before solving or printing the full lowered model.
  • Aligned the Python scalar ladder contract with the README/KDL scalar quickstart objective (3x + 2y with objective value 11.0). This keeps the first rung equivalent across Python and KDL instead of having two similar but different beginner models.
  • Fixed sparse Python array result extraction. For a VariableArray built with active=, inactive coordinates now round-trip through result.value(array) as nan while preserving the dense indexed shape. Previously the result accessor collected only active variables and attempted to reshape them into the dense shape.
  • Documented the sparse result-value behavior in migration notes so users upgrading to the ladder API know that inactive entries are explicit nan values rather than dropped coordinates.
  • Diagnostic UX follow-up: expanded the error-handling guide with the shared arco::<area>::<reason> diagnostic code namespace across Python exceptions and CLI/KDL JSON diagnostics. This is documentation, not yet a full shared diagnostic registry, but it gives users a stable automation contract for the codes already exposed by the implemented slices.
  • Diagnostic code cleanup: moved canonical validation failures off legacy uppercase strings such as TARGET_EMPTY_VARIABLE_SET and onto namespaced stable codes from arco-diagnostics, including arco::model::empty, arco::variable::invalid_bounds, and arco::target::empty_variable_set. This does not complete a full cross-surface registry, but it removes one inconsistent validation code path from the runtime facade.
  • Memory-first follow-up: added a larger active-mask regression that builds a 64 by 64 indexed domain with only the diagonal active. The test asserts dense_count == 4096, active_count == 64, and model.num_variables == 64. This keeps the test cheap while proving the public sparse API does not silently create the dense Cartesian variable set.
  • Composition diagnostics follow-up: added result.blocks.report(), an ordered per-stage report for composed solves. Each row includes stage order, block name, status, objective value, variable count, and constraint count. This is not a persisted workflow artifact yet, but it gives users a structured public object they can log or serialize without depending on private block internals.
  • Composition persistence follow-up: added result.blocks.report_json() as the persisted form of the same ordered stage report. This keeps stage reporting on a stable public block-results contract and avoids requiring users to reach into private block execution state to write workflow artifacts.
  • Solver contributor UX follow-up: made duplicate primitive ModelViewBackend registration fail explicitly instead of silently replacing the existing backend. The registry now has try_register for fallible registration, families for deterministic introspection, and replace for deliberate override/test paths. This makes solver-family ownership predictable for backend contributors.
  • Diagnostic ladder follow-up: added a Python contract test and error-handling documentation for SolverInvalidSettingError exposing arco::solver::invalid_setting. This widens the tested stable-code surface beyond array-shape errors and aligns solver configuration failures with the diagnostic namespace guide.
  • Shared labeled-axis follow-up: routed Python Model.add_variables(axes=...) through the shared arco-arrays::LabeledShape contract before constructing the variable array. This moves duplicate-axis rejection for variable arrays onto the same binding-agnostic shape semantics already used by params and labeled operands.
  • Shared labeled-axis follow-up: moved labeled bounds and labeled active mask shape parsing in the Python model-edit path onto the same arrays::labeled_shape_from_* helpers used by variable arrays. The active-mask regression uses a custom labeled object with duplicate axes so validation is proved at the shared shape contract even when the object was not created by arco.param.
  • Shared labeled-axis follow-up: routed Python named-axis reductions such as np.sum(x, axis=(i, i)) through the shared arco-arrays::LabeledShape lookup. Duplicate reduction axes now raise ArrayDimensionError instead of being silently deduplicated by binding-local parsing.
  • Solver conformance follow-up: added shared validate_model_view_solve_result validation at the ModelViewBackendRegistry boundary. Registered model-view backends now have their result fingerprint checked against the input model, must return one primal value per model variable, and may only omit optional vectors or return them in exact model order. Bad result shapes fail with SolverError::InvalidResultShape.
  • Data-backed KDL diagnostic follow-up: added shared diagnostic constants for arco::compile::csv and arco::semantic::csv, exposed them through Python's diagnostic-code registry, and covered missing data files in arco kdl check --materialize-data --format json. This keeps file-read failures in the same stable-code family as missing columns and invalid numeric values.
  • Debug/operations diagnostic follow-up: expanded arco-diagnostics and Python's arco.diagnostic_codes() to cover the current KDL source, semantic, and compile diagnostic namespace. The remaining rule is forward-looking: new CLI/KDL diagnostics should add a registry constant in the same change as the miette code.
  • Sparse/large-model follow-up: fixed KDL inspect variable instance counts for tuple-domain controls. Inspect now reports tuple-row cardinality on meta.counts.variable_instances and each variable record's instances field, while still showing component domain sizes in the set bindings. This keeps pre-solve memory estimates aligned with lowered model size instead of dense Cartesian products.
  • Data-backed KDL diagnostic follow-up: added materialized-check coverage for tuple-domain CSV shape errors. A missing tuple component column now has explicit CLI JSON test coverage through arco::semantic::missing_column, not only the scalar parameter materialization path.
  • Sparse/large-model memory follow-up: added solver-calibrated sparse matrix byte estimates to Python VariableArray.memory_estimate() and ExprArray.memory_estimate(). These fields use the same value/index/column-pointer accounting as model snapshots and are sized from active slots and linear terms so sparse active masks do not report a dense solver budget.
  • Solver backend conformance follow-up: converted the Xpress local-runtime small-LP integration smoke test to the shared check_small_lp conformance helper. The test still skips when no local Xpress runtime is installed and returns early for license initialization failures, so normal open/local CI does not require paid Xpress tooling.
  • Composition diagnostics follow-up: added result.blocks.diagnostics() and diagnostics_json() as the stable per-stage diagnostics payload for composed solves. Summary/model artifact policies now retain a stage_diagnostics.json file per block, tying solve status, objective value, result-vector sizes, model counts, and pre-solve memory estimates together without exposing block internals.
